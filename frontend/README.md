# frontend — DriveOn 웹 프로토타입

> 새로운 작업이나 방향이 다른 작업은 반드시 새 브랜치에서 진행한다. (예: `feature/frontend-로그인`) 자세한 규칙은 [루트 README](../README.md#작업-규칙) 참고.
>
> 이 폴더는 시연용 웹 프로토타입 전체(차량 화면 · POS · 데모 패널 · 둘러보기 · 대시보드)와, 화면을 띄우는 Node 서버(`server/`)를 함께 담고 있다.
> 실행은 이 폴더에서 `npm install` → `npm start`. 서버 부분은 나중에 `backend/`로 옮길 수 있다.

운전 중 Gleo에게 말로 주문하면, 내비 도착 시간을 역산해 **알맞은 시각에 매장으로 주문을 자동 전송**하는 차량 앱의 시연용 프로토타입입니다.
설계서(“DriveOn 팀 협업 설계서”)의 서버 · POS 시뮬레이터 · 데모 컨트롤 패널을 그대로 구현했고, 차량 앱은 Kotlin 앱 대신 **웹 화면**으로 만들었습니다.
API는 설계서 6번 계약을 따르므로 나중에 Kotlin(Pleos Connect) 앱이 같은 서버에 붙을 수 있습니다.

## 실행

Node.js 23.6 이상이 필요합니다(TypeScript를 빌드 없이 바로 실행). 런타임 의존성은 없습니다.

```bash
npm install      # 타입 검사용 TypeScript만 설치
npm start        # http://127.0.0.1:4173
```

| 주소 | 화면 |
| --- | --- |
| `/tour/` | **UI 둘러보기**: 23개 장면(주문 → 결제 → 전송 → 매장 → 포장 → 예외)을 ◀ ▶ 또는 목록 클릭으로 넘겨 보기. 장면마다 서버 상태를 다시 만들고, 화면 안을 직접 눌러도 됨. `#pay-done`처럼 장면 주소로 바로 열 수 있음 |
| `/dashboard/` | **차량 UI 대시보드**: 23개 장면 캡처를 한 장짜리 HTML로 묶은 것. 서버 없이 `dashboard/index.html`을 바로 열어도 됨(팀 공유·제출 자료용). 화면 속 버튼을 누르면 다음 장면, 아래 장면 띠·전체 보기·자동 재생 |
| `/` | 시연 무대: 차량 · POS · 데모 패널을 한 화면에 (영상 녹화용) |
| `/car/` | 차량 화면 (내비 + DriveOn 멀티 윈도우, Gleo 입력) |
| `/pos/` | 매장 POS 시뮬레이터 (시연의 마지막 화면) |
| `/demo/` | 데모 컨트롤 패널 (배속, 주행/정차, 정체, 결제 실패) |

- Gleo는 차량 화면 위쪽 상태바의 **Gleo 버튼**으로 부릅니다. 음성 인식은 Chrome·Edge의 Web Speech API를 쓰고, 마이크가 없으면 같은 자리에 뜨는 입력칸에 문장을 입력하면 됩니다. Gleo의 안내는 화면 위쪽에 잠깐 뜹니다.
- 음성 안내(🔊)는 브라우저 TTS입니다.
- 화면을 고친 뒤 대시보드를 다시 만들려면: `npm start` → `/tour/`에서 **대시보드용 캡처** 버튼(약 30초) → `npm run build:dashboard`.
  캡처는 `dashboard/snapshots/`에 장면별 JSON으로 저장되고, 대시보드는 `scripts/dashboard-template.html`을 틀로 만든다.
- 다른 기기(에뮬레이터 등)에서 접속하려면 `HOST=0.0.0.0 npm start`. Android 에뮬레이터에서는 `http://10.0.2.2:4173`.

## 화면 스타일

- 시스템 영역(상태바·내비·Gleo 입력)은 Pleos 야간 모드.
- DriveOn 앱 창은 배달앱식 밝은 화면: 홈(카테고리) → 가게 목록(별점·배달팁·최소주문) → 가게 화면(배달/포장 탭, 대표 메뉴) → 민트 장바구니 바 → 주문하기(수량·결제수단·결제금액) → 주문 현황(4단계).
  제목 글꼴은 우아한형제들의 BM 도현체·주아체(Google Fonts의 Do Hyeon·Jua, OFL 라이선스)를 쓰고, 로고·아이콘 이미지는 가져오지 않았다.
- 결제는 현대차 인카페이먼트를 기본으로 한 간편결제식 시트: 카드 넘겨 고르기 → 등록 차량(번호판)·운전자 프로필·디지털 키 자동 확인 → 정차 중이면 결제 비밀번호 6자리(보안 키패드), 주행 중이면 Gleo 음성 승인(“응”) → 결제 완료 → 카드사 앱 승인 알림.
  카드 면은 직접 그린 가상 카드이고, 모든 결제는 모의 결제다. 운전 중에는 “응” 한마디로도 결제된다.
- POS는 배달앱 사장님용 주문접수 화면식: 신규·처리중·완료 탭, 주문 상세, 큰 “접수하기” → “조리 완료” 버튼, 머리띠의 조리 시간(혼잡) 보정.
  매장이 접수하면 Gleo가 운전자에게 “○○에서 주문을 접수했어요”라고 알리고 차량 주문 현황도 “매장에서 조리 중이에요”로 바뀐다.
- 별점·리뷰 수·배달팁·최소주문금액은 모두 가상 값이다. 배달은 최소주문금액 이상이어야 하고 배달팁이 결제금액에 더해진다.

## 시연 순서 (설계서 2번 메인 시나리오)

1. `/`를 열고 데모 패널에서 **↺ 시나리오 처음으로** → 18:55 출발, 집 도착 예정 19:40
2. “글레오, 치킨 시켜줘” → 최근 주문 · 집 근처 · 가는 길 가게가 한 화면에
3. “이번엔 청양마요로” → “아니”(음료 X) → “배달” → 메뉴·금액을 읽고 결제 확인
4. “응” → 모의 결제 후 **“19:13에 매장으로 주문을 넣을게요”** (결제 직후 보내지 않음). 자동으로 30배속.
   화면은 내비가 넓어지고 아래에 미니바(“19:13 전송 · 18분 남음”)만 남는다. 미니바를 누르면 전송 대기 화면(시각 → 원인 문장 → 타임라인 → 메뉴)이 열린다.
5. 데모 패널 **🚧 정체 +6분** → 도착 19:46, 전송 시각 **19:19로 자동 조정**. Gleo가 한 번만 말한다:
   “정체로 도착이 6분 늦어져 전송도 19:13에서 19:19로 미뤘어요.” (30초 재계산으로 2분 미만 바뀌면 조용히 숫자만 바뀜)
6. 19:19가 되면 POS에 주문이 ‘딱’ 들어오고 Gleo가 “방금 주문을 넣었어요” 안내 → 1배속으로 복귀

그 밖에 보여줄 수 있는 장면:

- **지도의 '주문 전송' 깃발**: 결제하면 내비 경로 위에 📤 깃발(“19:13 여기서 주문 전송”)이 꽂힌다 = 이 지점을 지날 때 매장으로 주문이 들어간다. 아래 안내 바에도 📤 시각과 “N km 앞”이 나온다.
  - 위치는 서버 `dispatchPoint`(지금 차를 전송 시각까지 같은 규칙으로 미리 달려 본 자리). 전송되면 ✅ 회색 깃발로 그 자리에 고정.
  - 🚧 정체 → 전송 시각이 1분 넘게 바뀌면 깃발이 6초간 주황색으로 “~~19:13~~ → 19:16”을 보여 준다.
  - 정체가 길어 깃발이 0.3km 넘게 움직이면 원래 자리에 흐린 깃발과 주황 점선을 6초간 남긴다.
  - 서버는 같은 뜻의 `sendPoint`(눈금용, `predictKmAt`)도 계속 함께 준다.

- 데모 패널 **🚦 정차** → “메뉴판 보여줘”로 사진 메뉴판 → **🚗 주행**을 누르면 메뉴판이 미니바로 줄고 Gleo가 이어받음
- 결제 화면에서 배달/포장을 바꾸면 전송 시각이 달라짐 (포장은 매장 도착 기준)
- 호출 화면의 가게 카드 번호와 지도 핀 번호가 같다 → “두 번째 가게”처럼 번호로 고를 수 있음
- “가는 길에 있는 데로” → 길목치킨(+3분 우회) 포장 → 내비에 경유지 추가 → 매장 0.5km 전 “곧 길목치킨 판교점에 들러요” 한 번 안내 → 도착하면 POS에 차량번호와 함께 “고객 도착”
- “늘 먹던 걸로 시켜줘” → 한 번에 결제 확인
- 19:35 이후 주문 → “지금 바로 주문을 넣을게요. 도착 후 약 N분 뒤 …” (이미 늦은 경우)
- 💳 다음 결제 1회 실패, 전송 전 무료 취소 / 전송 후 취소 불가, POS 혼잡 보정(+5분 등)

## 구조

```
server/src/
  dispatch.ts        전송 시각 = 수령 지점 도착 예정 + 수령 여유 − 조리 − 배달(배달일 때만)
  car.ts             가상 차량: 주행·정차·정체, 내비 ETA, 포장 경유지 (NaviHelper·CarUxRestrictions 대역)
  orders.ts          주문 API 로직: 메뉴 검증 · 모의 결제 · 예약 · 30초 ETA 재계산 · 전송 · 취소
  payment.ts         PaymentProvider 인터페이스 + 모의 인카페이먼트 (어댑터만 바꾸면 실결제)
  recommend.ts       호출 화면 3묶음(최근 3건 · 집 반경 2km · 우회 5분 이내)
  gleo/nlu.ts        발화 → 의도 JSON (매장 메뉴 안에서만 찾음, LLM으로 교체 가능한 Nlu 인터페이스)
  gleo/dialog.ts     대화 흐름: 선택지 3개 이하 · 짧은 문장 · 결제 전 금액 읽기
  app.ts             시뮬레이션 루프 조립 (가상 시계, 30초 ETA 보고, 자동 빨리감기)
  index.ts           HTTP 서버: 계약 API + 시연 API + SSE + 정적 화면
vehicle-web/         차량 화면 (웹)
pos-sim/             매장 POS 시뮬레이터
demo-panel/          데모 컨트롤 패널
stage/               세 화면을 한 번에 보는 시연 무대
docs/contracts/      파트 간 인터페이스 계약 (설계서 6번 + 이 구현에서 정한 세부)
vehicle-app/         Kotlin(Pleos Connect) 앱으로 옮길 때의 안내
```

데이터는 모두 메모리에 있고 서버를 다시 켜면 처음 상태로 돌아갑니다. 매장 10곳과 메뉴는 가상 데이터입니다(상표 문제 예방).
